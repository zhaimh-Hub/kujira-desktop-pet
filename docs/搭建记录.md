## 3. 架构与数据流

**v1.2 起：桌宠这条线没有任何常驻服务。** 8080 静态服务和 8787 聊天代理都跑在 Electron 壳**自己的进程里**——点快捷方式才起，退出（`Ctrl+Alt+Q`）就一起关，开机不残留任何 python / node。

```
┌───────────── Electron 壳进程（点快捷方式才启动，退出即全没）─────────────┐
│                                                                        │
│  内置 http 服务 :8080 ──serve──▶ player 目录（example/*.html、dist/、    │
│                                   characters/*.livliv）                 │
│                                    │                                    │
│  BrowserWindow（透明窗口）─load─▶ pet-chat.html ──fetch──▶ 8080          │
│                                    │                                    │
│  chat-proxy.mjs（本进程内 import）:8787 ◀──POST /chat───────────────────┤
│                       │                                                │
└───────────────────────┼────────────────────────────────────────────────┘
                        │  （可选，壁纸线才需要）
                        ▼
        ┌───────────────┴────────────────┐
        ▼                                ▼
  api.deepseek.com                127.0.0.1:11434
  (deepseek-chat)                 (Ollama qwen3.5:4b)

  例外：Lively 壁纸是**独立进程**，它需要一个别人起的 8080，
  所以「大肥鱼当壁纸」这条线才要 serve-wallpaper.bat（python）。
  2026-11-06 起壁纸不再用大肥鱼，那条线默认不用起。
```

**为什么还需要「本地服务」这个概念**

- **静态服务**：页面是 ES module + `fetch()` 加载 `.livliv`，`file://` 直接打开会被 CORS 拦死，必须走 http。**但服务谁起都行** —— 以前用 python，现在壳自己起（更省事、无残留）。
- **聊天代理**：① 浏览器直连 `api.deepseek.com` 会被 CORS 拦；② API key 不能写进网页源码（等于公开）。代理把 key 留在进程内存里，页面只跟 `127.0.0.1` 说话。

**端口被占用时**：壳会先探测，8080/8787 上已有服务就**沿用**，不抢端口（所以你手动起的 python 也能兼容）。

## 4. 从零复现

### 4.0 前置（已具备）

```powershell
cd <PLAYER_DIR>
npm install          # 已有 node_modules
npm run build        # 产出 dist/（页面要用）
```

`dist/` 必须在，否则四个页面全部白屏（控制台会报 404 `/dist/index.js`）。

### 4.1 静态服务器（壳内置，已不需要 python）

**v1.2 起**：`main.js` 里自带一个 30 行的 http 服务，启动时把 `../player` 目录挂到 `127.0.0.1:8080`，退出时 `close()`。全流程零外部依赖：

```js
// main.js（节选）
const portTaken = (port) => new Promise((resolve) => { /* 探测端口 */ })
async function startStaticServer() {
  if (await portTaken(8080)) return          // 已有服务就沿用，绝不抢端口
  staticServer = http.createServer((req, res) => { /* 目录内静态文件 + MIME + 防穿越 */ })
  staticServer.listen(8080, '127.0.0.1')
}
app.whenReady().then(async () => {
  await startStaticServer()                  // 先起服务
  await startChatProxyInProcess()            // 再起聊天代理（同进程）
  createWindow()                             // 最后开窗口
})
app.on('will-quit', () => { staticServer?.close() })
```

`config.json` 里可调：`serveDir`（默认 `../player`）、`servePort`（8080）。

**python 那条老路（`example\serve-wallpaper.bat`）留着没删**，但它现在只服务**壁纸**这条线（Lively 是独立进程，需要一个别人起的 8080）。桌宠完全不需要它。

> ⚠️ 用绝对路径是有意的：本机裸 `python` 是 conda base 3.14（见环境手册 3.5）。
> ⚠️ `.bat` 必须 **GBK 编码 + CRLF 换行**，否则 cmd 会把中文注释当命令执行（见第 8 章坑 3）。

**开机自启**：**不需要，也已撤掉。** 2026-11-06 删除了 `启动\LivLiv静态服务器.lnk`；现在只有你点快捷方式（见 4.1.1）才起。

### 4.1.1 快捷启动大肥鱼（按需启动，不开机自启）

壳现在**自己**能起服务，所以「启动」就是启动一个 exe，不用再碰 bat / python。

| 方式 | 操作 | 说明 |
|---|---|---|
| 桌面图标「大肥鱼桌宠」 | 双击 | 目标直接是 `electron.exe`，**不闪黑框**，图标是角色头像 |
| **`Ctrl+Alt+F`** | 任何地方按 | 由 .lnk 自带的 Hotkey 实现，**不需要任何常驻进程**；只要那个 .lnk 还在桌面/开始菜单 |
| 开始菜单搜「大肥鱼」 | `Win` → 输入「大肥鱼」 | 适合不常点桌面的时候 |
| 桌面 `大肥鱼桌宠.bat` | 双击 | 备用（脚本/远程调用），会闪一下黑框 |

**快捷方式怎么重建**（换机/丢了就照这个来）：

```powershell
$ws = New-Object -ComObject WScript.Shell
$app = "<APP_DIR>"
foreach ($dir in @("$env:USERPROFILE\Desktop", "$env:APPDATA\Microsoft\Windows\Start Menu\Programs")) {
  $s = $ws.CreateShortcut((Join-Path $dir '大肥鱼桌宠.lnk'))
  $s.TargetPath        = "$app\node_modules\electron\dist\electron.exe"
  $s.Arguments         = "`"$app`""
  $s.WorkingDirectory  = $app
  $s.IconLocation      = "$app\assets\icon.ico"
  $s.Hotkey            = 'Ctrl+Alt+F'
  $s.Save()
}
```

> 快捷方式指向 exe 而不是 bat，是为了不闪控制台窗口；`start-pet.bat` 仍然保留，供脚本/命令行用。

### 4.3 卡片桌宠（Pennywise）

**先看清宿主**：Pennywise 0.8.0 是「把网址放进一个**永远置顶的浮窗**」的 Electron 壳，从 `app.asar` 里读到的主进程参数：

```
new BrowserWindow({ width: 700, height: 600, backgroundColor: '#16171a', autoHideMenuBar: true })
mainWindow.setAlwaysOnTop(true)
```

**没有 `transparent: true`**，设置里只有不透明度滑杆 → **透明页面在它里面必然显示成一块深灰**。所以：

- 页面底色直接用 `#16171a`（与窗口底色一致，看不出接缝）
- 内部再画一张「深海渐变 + 1px 描边 + 14px 圆角」的卡片 → 视觉上是浮起来的一张卡
- 内容区按 **700×550**（600 减去顶部导航条）设计，自适应缩放

**填入**：Pennywise 地址栏写
`http://127.0.0.1:8080/example/pet-card.html?char=p01`
或走它的 URL 投递端口：`http://127.0.0.1:6280/?url=<同上>`

**交互**：单击轮换表情、`Shift+单击` 戳一下（`player.poke()`，头发会甩）、双击 `hop`。

### 4.4 透明桌宠（PetShell，自建 Electron 壳）

```powershell
cd <APP_DIR>
$env:ELECTRON_MIRROR = 'https://npmmirror.com/mirrors/electron/'
npm install electron --no-audit --no-fund       # electron 40.10.6
# 启动：双击 start-pet.bat
```

**`main.js` 的关键几行**

```js
new BrowserWindow({
  transparent: true, backgroundColor: '#00000000',   // ← 透明
  frame: false, hasShadow: false, skipTaskbar: true,
  alwaysOnTop: true,
  resizable: false,        // ← 必须 false，见下面「拖动变大」那条坑
  webPreferences: { preload, contextIsolation: true, backgroundThrottling: false },
})
win.setAlwaysOnTop(true, 'screen-saver')             // 压得住全屏应用与任务栏
win.setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })
win.setIgnoreMouseEvents(true, { forward: true })    // 点击穿透（forward 让鼠标移动仍转发，眼睛还能跟随）
```

**拖动**在 `preload.js` 里做：`mousedown` 记起点 → `mousemove` 用 **`screenX/screenY`** 算增量（用 `clientX` 会因窗口自身移动而互相追着跑）→ 位移 >5px 才算拖动，并吞掉这次 `click`，避免「拖完顺手换了个表情」。

主进程侧**只能移动、不能带尺寸**，而且必须用 `setBounds` 把宽高钉死：

```js
ipcMain.on('pet:drag', (_e, dx, dy) => {
  const b = win.getBounds()
  win.setBounds({ x: Math.round(b.x + dx), y: Math.round(b.y + dy), width: cfg.width, height: cfg.height })
})
```

**托盘菜单**：显示/隐藏、点击穿透、重新加载、**大小（5 档 + 10% 微调）**、回到右下角、开发者工具、打开配置、**退出桌宠**。
**窗口尺寸只能在壳里改**（托盘 / 热键 / `config.json`），鼠标拖边框改大小是**故意关掉的**。

### 4.4.1 关闭桌宠的四个入口

### 4.5 让它说话（聊天代理 + TTS + 口型）

**后端**：`chat-proxy.mjs`（**v2：带工具调用的 agent**），零依赖，监听 `127.0.0.1:8787`。

| 接口 | 说明 |
|---|---|
| `GET /health` | `{ ok, provider, hasKey, tools:[...], tts:{engine,voice,exeOk}, ollamaModels }` |
| `POST /chat` | body `{ messages:[{role,content}], provider? }` → `{ reply, emotion, tools:[{name,ok,summary}], provider, model, usage, ms }` |
| `GET /tts?text=…&voice=…` | `audio/mpeg`（edge-tts 合成 + 磁盘缓存，命中直接返回） |
| `GET /tts/info` | `{ engine, voice, ok, ms }` — 自查用 |
| `GET /reminders?due=1` | 到点的提醒（取走即标记已送） |

**key 怎么进去**：优先 `process.env.DEEPSEEK_API_KEY`，没有就回退读
`HKCU\Environment\DEEPSEEK_API_KEY`（本机这个 key 是 User 级变量）。**不写任何文件、不进页面**。

**三种 provider**

| 值 | 行为 |
|---|---|
| `"deepseek"` | 只用云端 `deepseek-chat` |
| `"ollama"` | 只用本地 `qwen3.5:4b`（`think:false` 关掉思考，否则先烧一千多 token） |
| `"auto"`（当前默认） | 有 key 走 DeepSeek；云端失败**自动退回**本地；本地不可用又**自动退回**云端 |

**页面侧「说话」= 气泡 + 朗读 + 口型**

- 气泡：`#bubble`，显示 `后端 · 模型 · 耗时`；有工具调用时多一行 `🔧 打开应用 · 查系统`
- 朗读：**v1.3 起默认 edge-tts 真人音色**（见 4.7），失败自动退回 `speechSynthesis` 系统语音
- 口型：edge 音频走 `AnalyserNode` 取**真实振幅**（`mouthOpen = rms × 6.5`）；系统语音没有音量数据，用 `onboundary` 音节脉冲 + 正弦包络兜底
- 情绪：模型回复末尾带 `<emotion:smile|shy|angry|sad|surprised|neutral>`，代理剥离后返回 `emotion`，页面 `setExpression()` 3.2 秒后回 neutral

### 4.6 让它干活（agent 的 10 个工具）

代理里有一张 `TOOLS` 表（**27 个工具**），走 **OpenAI 函数调用协议**（DeepSeek 原生支持；Ollama 的 `/api/chat` 也支持 `tools`）。模型决定调哪个，**代理在本机执行**，结果回填后再让模型说人话——**最多循环 8 轮**（`maxToolRounds`），所以能跑「找文件 → 打开 → 记笔记」这种多步任务。

| 工具 | 干什么 | 安全措施 |
|---|---|---|
| `open_app` | 打开记事本/计算器/资源管理器/VS Code/Edge/Word/Excel/PPT/微信/QQ/Spotify/设置/任务管理器 | **白名单**（只认 `APP_WHITELIST` 里的名字），不执行任意命令 |
| `open_url` | 用默认浏览器开网页 | 只允许 `http/https` |
| `open_path` | 在资源管理器打开文件/文件夹 | 路径必须**已存在** |
| `system_info` | 时间、电量、内存、CPU、系统版本 | 只读 |

### 4.7 真人音色（edge-tts）

```powershell
& <PATH> -m pip install edge-tts   # 已装，落到 Python\Scripts\edge-tts.exe
& <EDGE_TTS_EXE> --list-voices | Select-String zh-CN
& <EDGE_TTS_EXE> --voice zh-CN-XiaoyiNeural --text "你好呀" --write-media out.mp3
```

- 默认音色 **`zh-CN-XiaoyiNeural`**（Cartoon/Lively，最像少女）；备选 `zh-CN-XiaoxiaoNeural`（温暖）、`zh-CN-YunxiaNeural`（可爱男声）
- 参数：`--rate +8% --pitch +10Hz`（在 `chat.config.json` 的 `tts` 段里改）
- 合成一次约 **2.3 秒**（首次），之后同句走磁盘缓存（`data\tts\<sha1>.mp3`）几乎瞬时
- 页面用 `?tts=edge|sapi` 切，**edge 失败一次就整体降级 SAPI**，不会反复卡住
- 口型借此升级成「真实振幅」：fetch mp3 → blob → `AudioContext` + `AnalyserNode` → 每帧 RMS

### 4.8 多步任务与实时进度（SSE）

一次指令可以连着调多个工具。代理每执行一步就通过 **SSE** 往页面推一行，页面把进度写在气泡里（黄色小字），所以看到的不只是「让我想想」：

```
data: {"type":"start","provider":"deepseek"}
data: {"type":"step","name":"system_info","phase":"run"}
data: {"type":"step","name":"system_info","ok":true,"summary":"查了系统状态","phase":"done"}
data: {"type":"step","name":"open_app","phase":"run"}
data: {"type":"step","name":"open_app","ok":true,"summary":"打开了记事本","phase":"done"}
data: {"type":"final","reply":"现在是上午十点十三分，记事本已经帮你打开啦。","emotion":"smile", ...}
```

- 页面用 `fetch('/chat?stream=1')` + `res.body.getReader()` 逐块解析，`phase:'done'` 的步骤累积成 `🔧 查了系统状态 · 打开了记事本`
- 实测「现在几点了，然后帮我打开记事本」→ 一条指令 **2 个工具、2.5 秒**
- 上限 `maxToolRounds: 8`，最后一轮强制不带工具（逼模型出文本），避免无限循环
- 不带 `?stream=1` 时仍是普通 JSON（兼容老调用）

### 4.9 联网搜索（web_search）

- 先请求 **`cn.bing.com/search`**（国内可达），失败再退 `html.duckduckgo.com`
- 只用正则从 HTML 里抠 `标题 + 链接 + 摘要`（各取前 5 条），**不引任何依赖**
- 实测：Bing 通、DDG 在本校网络 `fetch failed`；一次搜索+总结总耗时 **3.0 s**
- 模型拿到的是纯文本摘要，不会自己打开浏览器；要打开得再调 `open_url`（模型常这么干）

### 4.10 向量记忆（bge-m3）

- `remember` 时会用 Ollama 的 **`/api/embed` + `bge-m3`**（本地已有，1024 维）把内容算成向量存进 `memory.json`
- `recall` 用**余弦相似度**取 top5（阈值 0.45），老记忆没向量的会顺手补算
- 实测：记「我不喝咖啡，喜欢乌龙茶」→ 问「**我平时爱喝点什么呀？**」（字面几乎不重合）→ 正确答出「不喝咖啡，最爱乌龙茶」
- bge-m3 与对话模型会互相换出显存（`1.2 GB vs 6 GB`），所以 `remember` 首次会到 10 秒左右，之后恢复 1~2 秒

### 4.14 重复任务（schedule）

「每 30 分钟提醒我看一眼论文」这种持续性任务，存 `data\tasks.json`：

```json
{ "id": 1794018457983, "text": "看一眼论文！", "every": 60000, "left": 1, "next": 1794018594871 }
```

- 页面每 20 秒拉一次 `/reminders`；到点的任务会被返回、`left` 减 1、`next` 往后推一个 `every`
- `left = 0` 表示**一直重复**；`times` 传了就限次数
- 实测：设「每 1 分钟、共 2 次」→ 第 1 次请求返回该条、第 2 次空、`tasks.json` 里 `left` 2→1、`next` +60 s

### 4.15 语音开关（不自动出声）

- 右下角 **🔊/🔇** 一键静音，选择记在 `localStorage['pet:speak']`，重启仍生效
- URL 参数 `?tts=off` 强制静音

### 4.17 组合键与「写文件并保存」闭环

`press_key` 把 `ctrl+s` 这类字符串翻译成 SendKeys 序列（`ctrl`→`^`、`alt`→`%`、`shift`→`+`、`enter`→`{ENTER}`），交给 `win.ps1 -Action keys`。

**实测通过**：`open_app` 记事本 → `type_text "按键盘测试"` → `press_key ctrl+a` → `press_key ctrl+c` → 读剪贴板 = **「按键盘测试」**（证明组合键真的送到了目标窗口）。

**两个必须知道的限制**：

1. **按键只发给前台窗口**。`window` 参数会先 `AppActivate`（带中文别名：记事本→Notepad、计算器→Calculator、微信→WeChat…），但 Windows 有前台锁定，抢不到前台时按键会落到别的窗口。工具会把「找到了哪个窗口 / 有没有抢到前台」写进 summary，模型据此知道有没有真的生效。
2. **Win11 的记事本/计算器是 Store 应用**：`taskkill` 报成功但进程会被系统拉起，所以 `kill_app` 改成**前后进程计数**判定，杀不掉就如实说「没能关掉（0 → 0）」。

**v1.8 时**用 `qwen3.5:4b` 的 vision：能看懂界面结构，但**读不准小字**（让它读记事本里刚打的一行，它说「没看到记事本」）。

| 测试 | 结果 |
|---|---|
| 「屏幕上有什么字，原样念出来」 | ✅ 把屏幕上那段**学院会议纪要逐字念对**（朱刚、芦小兵、AI 冲击外语教学…） |

```
   → 只按回车（+ 点发送按钮兜底）→ 拉回桌宠
```

> **教训**：自动化对外发送，必须「**先给人看，再发**」。先发后问的自动化 + 真实社交软件 = 会替人发错消息。

#### ③ 为什么点不到微信输入框：桌宠压在上面

实测矩形：

```
桌宠窗口: L1343 T622 R1634 B1022
微信窗口: L44   T0   R1713 B1025
点击点 (85%, 95.5%) = (1463, 979)  → 落在桌宠窗口内 = True
```

**每次「点微信输入框」其实点在桌宠身上**，所以文字进不去、回车没反应。修正：

| 措施 | 做法 |
|---|---|
| 坐标 | 从 (50%, 92%) → **(85%, 95.5%)**（右侧聊天区的输入框） |
| 让位 | 自动化前把桌宠**挪到左上角**，做完挪回 |
| **不能用 `win.hide()`** | 隐藏窗口会**挂起渲染进程**，把进行中的 `fetch` 掐断 → 页面报 `Failed to fetch` |

#### ④ 焦点：`SwitchToThisWindow` 只改 Z 序，不改键盘焦点

症状：两个输入框的 caret 都在闪，但键盘输入仍进微信。

原因：`AppActivate` / `SwitchToThisWindow` 只把窗口拉到最前（看起来是活动窗口），**Windows 的键盘焦点并没有转移**。

修法：
- 新增 `POST /focuspet`：`focus 大肥鱼` + **在桌宠窗口上真实点一下**（`clickin 0.5,0.94`）——鼠标点击才是 Windows 认定「接收键盘输入」的动作
- 有效：`/focuspet` 返回 `{"ok":true,"focused":"大肥鱼 · 会干活的桌宠"}`

#### ⑤ 页面侧的四个真 Bug（都是静默失败）

| Bug | 现象 | 根因 |
|---|---|---|
| `history.push is not a function` | 一发消息就崩、界面没反应 | `let history` 声明丢了 → 指向 `window.history` |
| `steps is not defined` | 崩在 `steps.length = 0` | 声明丢失 |
| `showSteps is not defined` | 收到进度事件就崩 | 函数丢失 |
| **按 ↑ 箭头不发送、回车能发** | 点击无反应 | `addEventListener('click', send)` 把 `MouseEvent` 当 `overrideText` 传了进去 |

> 共同点：**整条链路静默断掉**，桌面上一片安静，只有 `pet-shell.log` 里有 `Uncaught`。已在错误兜底里加 `gotReply` 区分「真没连上」与「答复已到、后续出错」。

#### ⑥ 确认路径必须回 SSE

页面用 `?stream=1` 按 SSE 解析。若「用户回确定」那条快捷路径返回**普通 JSON**，页面前面收不到 `data:` 就会判「流断了」→ 冒「代理没连上」。

修法：确认路径也 `res.writeHead(200, {'content-type':'text/event-stream'})` 并写一条 `{"type":"final"}`；整段包 `try/catch`，出错也回 `final`。

#### ⑦ 停止键（部分完成）

- ✅ `send()` 里建 `AbortController`，请求带 `signal`；工作中点发送键 = `abort()`，气泡显示「好，停了。」
- ⚠️ **视觉状态没做成**：`#send.busy`（红底圆角方块 ■）已写样式，但 `setBusy(true)` 的时序没对齐，工作时不显示

## 8. 坑与解法

| # | 现象 | 原因 | 解法 |
|---|---|---|---|
| 1 | 页面直接 `fetch` DeepSeek 报 CORS | 云端 API 不返回 `Access-Control-Allow-Origin` | 走本地代理 8787（代理自己加 CORS 头） |
| 2 | key 写进网页 = 公开 | 前端资源对谁都可见 | key 只在代理进程内存里，页面只连 `127.0.0.1` |
| 3 | `.bat` 一运行冒一堆 `'le' 不是内部或外部命令` | 文件是 **UTF-8 + LF**，cmd 按 GBK 逐字节解析，中文注释把行拆坏 | 用 **GBK(936) 编码 + CRLF** 写：`[IO.File]::WriteAllText($p, ($lines -join "`r`n"), [Text.Encoding]::GetEncoding(936))` |
| 4 | `electron.exe .` 起来就 `app.requestSingleInstanceLock is undefined` | 环境里带 `ELECTRON_RUN_AS_NODE=1`，Electron 退化成纯 Node，`require('electron')` 只返回 exe 路径字符串 | bat 里 `set "ELECTRON_RUN_AS_NODE="`；判断依据：`process.versions.electron` 有值但 `typeof require('electron')==='string'` |
| 5 | `Lively.exe setwp --file <网址>` 无效 | `setwp` 只查库内条目，不走导入 | 做成库内条目（`LivelyInfo.json` + `index.html`），或用 UI 添加 |
| 6 | Lively 每换一次壁纸就在 `%TEMP%\Lively Wallpaper\CEF\` 留一份 Chromium 档案，**从不回收**（实测 21 份 / 399 MB） | 每个壁纸实例独立 user-data-dir | `Lively.exe closewp` → 删 `CEF\*` → 重新应用；这是**周期性维护项** |
| 7 | 透明页放进 Pennywise 变深灰卡片 | 宿主窗口 `backgroundColor: '#16171a'` 且没开 `transparent` | 用 `pet-card.html`（底色与窗口一致 + 自己画卡片） |
| 8 | 设 420×580 却占掉半个屏幕 | 150% 缩放下 1 DIP = 1.5 px | 按 ×1.5 心算，或直接看托盘菜单「当前：宽×高」 |
| 9 | 拖完宠物顺手换了表情 | `click` 在 `mouseup` 后照常触发 | preload 里拖动后设标记，`click` 捕获阶段 `stopPropagation` |
| 10 | 角色右下角有 LivLiv 角标，去不掉 | 角标来自模型包 `meta.watermark`，播放器只是照画 | 换自己导出的模型；代码层面没有开关 |
| 11 | `npm install electron` 之后没有 `dist/electron.exe` | npm 11 的新 `allowScripts` 策略跳过了 postinstall | 装完检查 `node_modules/electron/dist/electron.exe`；缺了就跑 `node node_modules/electron/install.js`（带 `ELECTRON_MIRROR`） |
| 12 | `winget install` 静默挂 15 分钟 | 下载走 GitHub Release，校园网下极慢且不报错 | 走 gh-proxy + aria2（见 4.2），装前校验 SHA256 |
| 13 | Ollama 回答慢 20 秒 | 默认 `think=true`，先烧一两千思考 token | 代理里固定 `think:false`（原生 `/api/chat` 才认） |
| 14 | 壁纸 + 桌宠 + Ollama 同时开，风扇狂转 | 显存 8 GB 里 Ollama 占 ~6 GB，壁纸 WebView2 + Electron 再抢 | 本地模型聊天时先暂停壁纸；或改用 DeepSeek（不占显存） |

```powershell

win.on('resize', () => log(`注意：窗口尺寸被外部改变 ${w}×${h}（配置是 …）`))
```
